# 网页五子棋 Demo 实施计划

状态：首版已实现，完成服务端和双网页对局验收；验证范围与剩余限制见文末。

## 1. 范围

- 单节点部署，Auth、Gate、Logic、Room 各运行一个实例；Logic 和 Room 是独立服务进程。
- 服务发现统一使用 Consul，本地调试和容器部署使用同一方案；本 Demo 不提供 Static 模式切换。
- 网页双人五子棋：演示账号登录、创建房间、输入房间号加入、准备、轮流落子、胜负展示、再来一局和退出。
- 15 × 15 棋盘，无禁手，连续五颗或更多同色棋子获胜，棋盘填满且无人获胜则和棋。
- 对局由服务端判定。房间和对局保存在 Room 内存，玩家当前 `roomID` 保存在 Logic 的 room 模块内存；不额外增加操作中标记。
- 首版不支持断线重连续局，不保留断线席位，也不自动重连。断线按退出处理，对局中判负；刷新或再次连接需要重新登录，回到大厅，不恢复原对局。
- 进程重启不恢复对局；客户端应能处理房间不存在，回到加入/创建界面。
- 保留已有背包示例，不增加对局奖励、战绩数据库、匹配、观战、聊天、商城。
- 不考虑多节点：不设计分片、房间节点归属、迁移、租约、故障转移或分布式事务。
- 实现按下列阶段落地；保留已确认的简化边界。

## 2. 已确认的调用边界

```text
认证：     网页 → Gate → Auth
登录：     网页 → Gate → Logic / User Actor
创建/加入/退出：网页 → Gate → Logic / User Actor / room 模块 → Room 内部 RPC
准备/落子/快照：网页 → Gate → Room 客户端 RPC → Room Actor
断线清理： Gate → Logic.OnDisconnect → room 模块 → Room 内部退出 RPC
房间推送： Room → Gate → 网页
```

改变玩家房间归属的创建、加入、退出经过 Logic；准备、落子、房间快照直接进入 Room。Logic 负责限制玩家同时只在一个房间，Room 负责房间成员与对局规则。

再次登录不把新连接接续到旧房间。顶号先清理旧连接的房间成员，再完成新登录；旧断线通知只能作用于旧成员记录。

| 所属位置 | 职责 |
| --- | --- |
| Auth | 演示账号认证、角色 ID、Token；不持有房间状态 |
| Logic / User Actor | 玩家资料、登录连接、已有玩家模块 |
| Logic / room 模块 | 当前 roomID；创建/加入前赋值，失败清空，退出成功后清空；调用 Room 内部 RPC |
| Room 服务 | Room Actor 容器、内部创建/加入/退出编排、房间清理；不另建全局玩家归属索引 |
| Room Actor | 成员、座位、准备状态、棋盘、回合、对局版本、结果 |
| Gate | 连接、可信会话信息、服务转发、推送 |

玩家归属操作由 User Actor 内的 room 模块编排，Room Actor 保存本房间实际成员。以非空 roomID 拦截再次创建或加入，不引入业务操作 ID、成员版本、通用幂等机制或操作结果查询接口。Gate RequestID 只用于关联一次请求与响应。

采用简单的 RPC 成败处理，不保证跨服务原子一致性。接受服务端已执行而响应丢失时可能产生的异常不一致，不为此增加自动重试、结果确认或补偿流程。

## 3. 源码核实与接入方案

### 实施前核实的现状

- Atlas `gate/server.go` 的 `forward` 校验公开服务名称，透传业务负载；不解析 `room_id`。
- Gate 按目标服务读取连接绑定，将绑定值写入 shard key，并注入可信的 `GateID + SessionID`。
- 当前 `internal/auth/service.go` 只为 Logic 客户端服务绑定角色 ID；尚无 Room 绑定。
- 当前 `api/logic/manager.go` 把 Logic 请求放进 User Actor，并对非 Login 客户端请求校验当前登录连接。
- Atlas `gate/disconnect.go` 的断线回调固定发给 Logic，不会自动通知 Room。
- Actor Manager 可以用于 Room，但拒绝携带 Actor 执行上下文的本地嵌套 Add/Exec/Delete；两服务通过生成的 RPC 函数通信。
- Gate 已支持 WebSocket，示例现已只启用 WebSocket。
- 当前 `scripts/generate.bat` 使用 protoc 生成 Go/gRPC，并为 Room 生成内部 RPC 和 Push 辅助代码。

### 单节点接入方向

1. 定义 `room.client.v1.RoomClientService` 和 `room.server.v1.RoomServerService`；Room 公开入口不提供创建、加入或退出，它们只由 Logic 调用内部接口。
2. Room 客户端服务的 Gate 绑定值采用可信角色 ID。绑定在 Logic 校验登录后的创建/加入流程中建立，不接受客户端自报身份。
3. Room 从 shard key 读取玩家身份，从上下文读取来源连接；从请求读取 `room_id`，在本服务内按房间 ID 调用 Room Actor。
4. `room_id` 是目标，不是权限证明。Room Actor 校验角色 ID 和连接是否匹配创建/加入时登记的成员，再检查座位和回合。
5. 不提供断线恢复用的 GetCurrentRoom。当前房间关联由 Logic room 模块用于约束创建、加入和退出；在线快照仅用于当前成员同步状态。
6. Room 内部 RPC 使用生成的服务函数，Push 使用生成的推送辅助代码；业务遵守框架调用规范。

这里 shard key 承载 Room 客户端请求的玩家身份，Room Actor 的 key 来自业务请求；二者不混用。单实例无需让 Gate 解析棋类业务协议，也无需修改线协议来选择 Room 节点。

### 第一阶段必须定稿的成员与断线契约

Room 绑定角色 ID 只能证明该连接的身份，房间访问还必须匹配本次加入的成员连接。首版不建立全局连接登记及重连接管机制：

- 创建/加入时由 Logic 传入可信角色 ID、GateID、SessionID；Room 保存到成员记录，不能由客户端自报这些字段。
- 固定断线回调由 Logic 转告 Room，调用退出接口，携带房间 ID、角色 ID 和旧连接；只清理匹配房间、玩家及 GateID + SessionID 的成员。
- 对局中断线/顶号退出判负并通知对手；等待或结算状态直接释放席位。新连接不会继承旧席位。
- Logic 在调用创建/加入 RPC 前先赋值 roomID。RPC 等待会让出 User Actor 执行权，期间再次创建/加入会被非空 roomID 拦截；RPC 失败清空，成功保留。
- 顶号时由登录流程显式清理旧成员，不能只依赖稍后到达的旧连接断线回调。Room 完成旧成员退出后，旧请求不能再提交状态；随后新连接才能完成登录并重新入房。
- 退出成功后才清空 roomID，失败保留并报告错误，不增加待清理状态或后台重试。退出完成前再次加入仍报已在房间。
- 断线通知可能丢失或失败，不承诺异常情况下立即清理或自动收敛；不为此增加可靠通知、补偿或重试机制。
- 成员及连接校验在 Room Actor 内执行；不新增成员版本。创建/加入和断线交错作为异常场景记录，不扩展成事务协调流程。

以上优先在 example 内实现，不预设修改 Atlas。第一阶段以测试确定身份绑定、成员退出和登录提交顺序；若发现框架缺口，先记录具体缺口和最小修改范围，再进入后续阶段。

## 5. 协议和状态约定

接口名称可在协议落地时微调，语义保持如下。

| 入口 | 操作 | 关键约定 |
| --- | --- | --- |
| Logic Client | CreateRoom | roomID 非空则拒绝；生成房间 ID 并先赋值，再调用 Room；失败清空 |
| Logic Client | JoinRoom | roomID 非空则拒绝；先赋目标房间 ID，再调用 Room；失败清空 |
| Logic Client | LeaveRoom | 调用 Room 退出；成功后才清空 roomID，失败保留 |
| Room Server | CreateRoom / JoinRoom | 接收房间 ID、可信玩家身份和连接；创建者自动占一席；满员拒绝 |
| Room Server | LeaveRoom | 按房间、玩家、连接匹配退出；对局中判负；断线调用此接口 |
| Room Client | GetRoom | 返回完整快照；首版只允许成员读取 |
| Room Client | Ready | 成员准备；双方准备后开局；结算后双方重新准备开始下一局 |
| Room Client | PlaceStone | 房间 ID、坐标；在 Actor 内校验成员、对局状态、回合及空位 |
| Room Push | RoomUpdated | 完整快照，包含房间 ID 和房间生命周期内递增的快照版本 |

- 两个座位；房主执黑，另一方执白。房主退出后，留下者接任房主。
- 正常调用流程中，一名玩家同时只占用一个 roomID。创建时 Logic 生成新房间 ID，加入时使用目标房间 ID，均在 RPC 前赋值；Room 创建接口校验房间 ID 未占用。该 ID 是业务实体 ID，不是操作 ID。
- 创建/加入失败直接清空 roomID；退出成功才清空，退出失败保留。不引入额外的 pending、操作中或成员代次字段。
- 普通客户端请求不得隐式创建 Room Actor。不存在即返回明确的房间不存在错误。
- 断线按退出处理，不保留席位；网页禁用对局操作并提示重新登录。再次登录清理旧归属后进入大厅，不恢复棋盘或原席位。
- 首版不增加落子倒计时。空房立即回收；不增加无活动定时回收及跨服务清理通知，异常残留随进程重启清除。
- 所有业务操作都不增加操作 ID，不保存去重结果，也不配置业务自动重试。客户端等待请求结束期间禁用对应按钮，失败展示错误；断线后不重放旧命令。
- 落子状态提交后，推送失败不回滚棋盘；仍在线的成员可通过快照同步。超时不自动重发落子。
- 状态提交并构造独立快照后再执行推送；发送中的负载保持不可变。推送等待可能让出 Actor，客户端按版本丢弃旧快照。
- 快照版本只用于显示顺序，不作为业务操作 ID、成员版本或请求去重机制。

## 7. 界面预览约定

早期会话预览仅为本地模拟。此前同源部署已通过两个账号的浏览器验收；当前改为本机前端 `http://127.0.0.1:5173` 直连 Gate。下图来自真实服务对局：

![真实双人对局](gomoku-demo.jpg)

- 整体：简洁棋室风格，低饱和绿色、木色棋盘；优先突出棋盘，不添加运营系统或无关统计卡片。
- 登录页：演示账号输入和进入大厅按钮，明确演示账号语义。
- 大厅：创建房间、输入房间号加入；不提供公开房间列表或自动匹配。
- 对局页：左侧 15 × 15 棋盘，右侧双方身份/执子、当前回合、连接状态；顶部显示房间号和退出入口。
- 等待状态：展示空席与邀请提示；成员到齐后可准备开始。预览中的“模拟好友加入”不进入正式产品。
- 结算状态：胜负结果与再来一局；正式退出流程在对局中应提示判负后果。
- 断线状态：立即禁止落子，提示断线按退出处理、对局中判负，提供重新登录入口；不展示恢复对局按钮。

- 小屏设备将侧栏移到棋盘下方；正式实现需验证触摸落点精度和误触处理。
- 预览中的登录/大厅/对局切换导航只用于评审，不作为正式游戏导航。

## 8. 验证与完成条件

- 规则测试：四个方向获胜、棋盘边界、占用位置、错误回合、和棋、结算后禁止落子。
- 编排测试：非空 roomID 拒绝创建/加入；RPC 等待期间重复加入被拦截；创建/加入失败清空；退出成功清空、失败保留。
- 接入测试：可信身份、服务公开边界、按房间 ID 分发、房间成员连接校验。
- 断线测试：对局中判负、等待时释放席位、再次登录不恢复对局；旧连接通知不清理新连接。
- 客户端测试：失败不自动重试、等待时禁用对应按钮、乱序快照不回退、断线命令不重放。
- 运行协议生成及生成一致性检查、`go test ./...`、`go vet ./...`、项目构建与 lint；前端执行其类型检查和构建。
